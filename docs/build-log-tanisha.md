## 4. How phoneme-to-viseme mapping works, explained
A viseme is a mouth shape rather than a single speech sound. Many different phonemes look almost identical from the outside, so the animation system groups them into a smaller set of visible shapes. In this build, the mapping collapses the phoneme inventory into a handful of mouth poses such as bilabial, fricative, dental, velar, and vowel shapes. That means the viewer can see the broad target shape, but the system cannot perfectly distinguish every sound by appearance alone. Groups such as P/B/M, S/Z, K/G, and TH/DH share the same visible mouth posture, so the animation is best used as a teaching aid for general articulation placement rather than as a perfect phonetic classifier.

## 5. How the timeline works
The timeline module converts a phoneme sequence into a series of timed keyframes with a neutral lead-in and lead-out. Vowels are given longer durations than stops because they are visually more salient and easier to perceive, while stops are shorter and more percussive. Each frame is blended into the next over a short cross-fade so the mouth does not snap abruptly between poses. Without that cross-fade, the animation would look rigid and less readable for learners.

## 6. Path A vs Path B
Path A is the 3D avatar using morph targets in the browser. Path B is the fallback clip system that renders a local video file for the current phoneme. The current implementation keeps Path A active by default through the Avatar component, while the UI can switch the entire component to the fallback by changing the USE_CLIPS constant in frontend/src/components/Articulation.jsx to true. The fallback is working and safe even when the video file is missing because the component silently hides the broken video element. Path A is functional as a local render path, but the final mouth shapes still depend on the runtime asset and its actual morph target names.
